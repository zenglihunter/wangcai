1. Qdrant 是干嘛的？

你可以把 Qdrant 理解成一个“专门存向量的数据库”。

普通数据库适合：

  • 按 ID 查
  • 按条件筛选
  • 精确匹配

Qdrant 适合：

  • 语义搜索
  • 相似内容召回
  • RAG（让 AI 先检索资料再回答）
  • 商品、文章、图片等“找相似内容”

比如：

你输入一句：

帮我找 Arista 的低延迟交换机

系统会先把这句话转成向量，再去 Qdrant 里找“语义最接近”的商品。

3. 一条数据长什么样？

你库里的一条商品数据大概像这样：


{
  "id": "00004b73-8694-5cc5-b15c-d4af86ad5267",
  "payload": {
    "pageContent": "SKU: ARI:DCS-7130-96LBAS-R | Brand: Arista | Type: Switch | Model: DCS-7130-96LBAS-R | Price: $0 | InStock: FALSE | Name: DCS-7130-96LBAS-R, Arista 7130LS Switch, 96x1GbE SFP/Ultra Low Latency/Redundant PSU | URL: https://www.router-switch.com/dcs-7130-96lbas-r.html",
    "metadata": {
      "sku": "ARI:DCS-7130-96LBAS-R",
      "brand": "Arista",
      "name": "DCS-7130-96LBAS-R, Arista 7130LS Switch, 96x1GbE SFP/Ultra Low Latency/Redundant PSU",
      "type": "Switch",
      "model": "DCS-7130-96LBAS-R",
      "url": "https://www.router-switch.com/dcs-7130-96lbas-r.html",
      "small_image": "https://media.router-switch.com/media/catalog/product/a/r/arista.jpg",
      "created_at": "2024/7/1 2:51",
      "is_in_stock": "FALSE",
      "price": "$0"
    }
  }
}

简单理解：

  • id：这条数据的唯一编号
  • payload：附加信息，也就是你真正想返回给业务系统的内容
  • pageContent：给 AI 检索用的一段主文本
  • metadata：结构化字段，方便后续过滤

4. 最常见的使用方式

用法 1：查库里有哪些 collection


curl http://127.0.0.1:6333/collections

作用：

  • 看当前有哪些数据表（collection）

用法 2：看某个 collection 的详情


curl http://127.0.0.1:6333/collections/rs-product

作用：

  • 看向量维度
  • 看距离类型（Cosine / Dot 等）
  • 看 collection 配置

用法 3：看有多少条数据


curl -X POST http://127.0.0.1:6333/collections/rs-product/points/count \
  -H 'Content-Type: application/json' \
  --data '{"exact": true}'

作用：

  • 看 rs-product 里总共有多少条记录

用法 4：随机翻几条数据出来看看


curl -X POST http://127.0.0.1:6333/collections/rs-product/points/scroll \
  -H 'Content-Type: application/json' \
  --data '{"limit": 3, "with_payload": true, "with_vector": false}'

作用：

  • 抽样检查导入的数据是不是正常
  • 看 payload 字段结构

这一步特别适合排查：

  • 字段名对不对
  • 文本有没有空值
  • URL、SKU、品牌有没有导错

5. 真正开始“使用”Qdrant 的核心流程

Qdrant 真正工作的流程，通常是这 4 步：

第 1 步：准备文本

比如一条商品：

  • 品牌：Arista
  • 型号：DCS-7130-96LBAS-R
  • 类型：Switch
  • 名称：Arista 7130LS Switch

你把它整理成一段适合检索的文本，例如：


SKU: ARI:DCS-7130-96LBAS-R | Brand: Arista | Type: Switch | Model: DCS-7130-96LBAS-R | Name: DCS-7130-96LBAS-R, Arista 7130LS Switch, 96x1GbE SFP/Ultra Low Latency/Redundant PSU

这就是你现在 pageContent 在做的事情。

第 2 步：把文本转成向量（Embedding）

Qdrant 本身不负责生成向量。

你需要用别的模型来生成 embedding，比如：

  • OpenAI embedding
  • Gemini embedding
  • BGE
  • Voyage AI
  • 本地 embedding 模型

比如你把一段文本转成一个 1536 维数组：


[0.0123, -0.0388, 0.2291, ...]

然后再存进 Qdrant。

第 3 步：把向量和 payload 存进 Qdrant

也就是“入库”。

你现在这一步已经做过了。

入库时，一般会存：

  • id
  • vector
  • payload

第 4 步：查询时，把用户问题也转成向量，再去搜

例如用户问：

找一款 Arista 的低延迟交换机

流程是：

  1. 把这句话转成向量
  2. 用这个向量去搜 rs-product
  3. 返回最相近的几条商品
  4. 再把结果展示出来，或者交给 AI 总结

这就是 Qdrant 最核心的用法。

6. Python 最小可用示例

先安装客户端：


pip install qdrant-client

示例 1：连接 Qdrant 并查看 collections


from qdrant_client import QdrantClient

client = QdrantClient(url="http://127.0.0.1:6333")

collections = client.get_collections()
print(collections)

示例 2：统计 rs-product 条数


from qdrant_client import QdrantClient

client = QdrantClient(url="http://127.0.0.1:6333")

count = client.count(
    collection_name="rs-product",
    exact=True
)

print(count)

示例 3：滚动读取几条数据


from qdrant_client import QdrantClient

client = QdrantClient(url="http://127.0.0.1:6333")

points, next_page = client.scroll(
    collection_name="rs-product",
    limit=3,
    with_payload=True,
    with_vectors=False
)

for p in points:
    print("ID:", p.id)
    print("Payload:", p.payload)
    print("-" * 50)

7. 如果要做“相似搜索”，你还差什么？

你还差的是：

1）一套 embedding 模型

如果你的 rs-product 向量维度是 1536，那说明你大概率用的是某种 1536 维 embedding 模型。

重点是：

查询时必须用同一套 embedding 模型。

否则会出现：

  • 搜索结果不准
  • 明明有数据却召回很差
  • 相似度看起来很奇怪

2）一段查询代码

伪代码是：


query = "arista low latency switch"
query_vector = embedding_model.embed_query(query)

results = client.search(
    collection_name="rs-product",
    query_vector=query_vector,
    limit=5
)

然后从 results 里取出：

  • 分数
  • 名称
  • SKU
  • URL
  • 品牌

如果你是小白，我建议按这个顺序来：

第一阶段：先学会“看库”

你先熟悉这些命令：

  • 看 collections
  • 看条数
  • 看样本数据
  • 看某个 collection 配置

只要这几步熟了，你对 Qdrant 就不会陌生。

第二阶段：做一次真实检索

目标：

输入一句话，比如：

  • Arista low latency switch
  • Juniper license
  • 400GE modular switch

然后从 rs-product 里搜出最相关的几条。

这一步是从“有数据库”变成“真的用起来”的关键。

第三阶段：给 AI 接上 RAG

典型用法：

  1. 用户提问
  2. 先去 Qdrant 检索商品资料
  3. 把检索结果交给大模型
  4. 大模型基于检索结果回答

比如：

推荐一款适合数据中心的 400GE 交换机

系统就能从 rs-product 找到 H3C、Arista、Cisco 等相关商品，再生成回答。

9. 你这个库目前的一个小优化建议

你现在的 payload 里，很多字段存了两份：

  • 外层一份
  • metadata 里一份

例如：

  • brand
  • name
  • type
  • model
  • url
  • price

这不是严重问题，但后面建议你统一一下。

推荐做法

二选一：

#### 方案 A：只保留扁平字段


{
  "sku": "...",
  "brand": "Arista",
  "name": "...",
  "type": "Switch",
  "model": "...",
  "url": "..."
}

优点：

  • 查询方便
  • 过滤简单

#### 方案 B：只保留 metadata


{
  "pageContent": "...",
  "metadata": {
    "sku": "...",
    "brand": "Arista"
  }
}

优点：

  • 结构更清晰
  • 业务字段更集中

对你来说，如果以后要做筛选和接口返回，我更倾向：

保留扁平字段 + pageContent

这样后面开发最省事。

10. 常见坑

坑 1：查询时 embedding 模型不一致

这是最常见的大坑。

入库用 A 模型，查询用 B 模型，结果通常会歪掉。

坑 2：向量维度不一致

比如 collection 要的是 1536 维，但你传了 1024 维，就会报错。

坑 3：只导入了 payload，没有导入 vector

这样表面上看数据在，实际上没法做向量搜索。

坑 4：pageContent 太差

如果文本拼得太随便，检索效果会明显下降。

好的 pageContent 应该尽量包含：

  • 品牌
  • 型号
  • 类型
  • 关键规格
  • SKU
  • URL（可选）

坑 5：以为 Qdrant 自己会“理解文本”

不会。

Qdrant 只负责：

  • 存向量
  • 做近邻搜索
  • 返回结果

真正“把文本变聪明”的是 embedding 模型。
