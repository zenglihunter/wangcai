Qdrant 小白入门使用文档

这份文档是给“已经把 Qdrant 跑起来，也已经导入了一批数据，但还不太清楚后面怎么用”的人准备的。

你现在的环境已经确认：

  • Qdrant 可访问：http://若干.若干:若干
  • 当前已有多个 collection
  • 其中 rs-product 已导入 若干 条数据

若干. Qdrant 是干嘛的？

你可以把 Qdrant 理解成一个“专门存向量的数据库”。

普通数据库适合：

  • 按 ID 查
  • 按条件筛选
  • 精确匹配

Qdrant 适合：

  • 语义搜索
  • 相似内容召回
  • RAG（让 AI 先检索资料再回答）
  • 商品、文章、图片等“找相似内容”

比如：

你输入一句：

帮我找 Arista 的低延迟交换机

系统会先把这句话转成向量，再去 Qdrant 里找“语义最接近”的商品。

若干. 你现在库里有什么？

目前已发现这些 collection：

  • star_charts — 若干 条
  • products — 若干 条
  • rs-product — 若干 条
  • midjourney — 若干 条
  • terraforming — 若干 条

其中最像“主业务数据”的是：

  • rs-product
  • products

特别是 rs-product，很适合拿来做 router-switch.com 的商品检索或 AI 问答检索。

若干. 一条数据长什么样？

你库里的一条商品数据大概像这样：

 { "id": "若干4b7若干-若干-5cc5-b15c-d4af86ad5若干", "payload": { "pageContent": "SKU: ARI:相关型号 | Brand: Arista | Type: Switch | Model: 相关型号 | Price: $若干 | InStock: FALSE | Name: 相关型号, Arista 若干0LS Switch, 若干6x1GbE SFP/Ultra Low Latency/Redundant PSU | URL: https://www.router-switch.com/dcs-若干-若干6lbas-r.html", "metadata": { "sku": "ARI:相关型号", "brand": "Arista", "name": "相关型号, Arista 若干0LS Switch, 若干6x1GbE SFP/Ultra Low Latency/Redundant PSU", "type": "Switch", "model": "相关型号", "url": "https://www.router-switch.com/dcs-若干-若干6lbas-r.html", "small_image": "https://media.router-switch.com/media/catalog/product/a/r/arista.jpg", "created_at": "若干/若干/若干 某时段", "is_in_stock": "FALSE", "price": "$若干" } } }

简单理解：

  • id：这条数据的唯一编号
  • payload：附加信息，也就是你真正想返回给业务系统的内容
  • pageContent：给 AI 检索用的一段主文本
  • metadata：结构化字段，方便后续过滤

若干. 最常见的使用方式

用法 若干：查库里有哪些 collection

 curl http://若干.若干:若干/collections

作用：

  • 看当前有哪些数据表（collection）

用法 若干：看某个 collection 的详情

 curl http://若干.若干:若干/collections/rs-product

作用：

  • 看向量维度
  • 看距离类型（Cosine / Dot 等）
  • 看 collection 配置

用法 若干：看有多少条数据

 curl -X POST http://若干.若干:若干/collections/rs-product/points/count \ -H 'Content-Type: application/json' \ --data '{"exact": true}'

作用：

  • 看 rs-product 里总共有多少条记录

用法 若干：随机翻几条数据出来看看

 curl -X POST http://若干.若干:若干/collections/rs-product/points/scroll \ -H 'Content-Type: application/json' \ --data '{"limit": 若干, "with_payload": true, "with_vector": false}'

作用：

  • 抽样检查导入的数据是不是正常
  • 看 payload 字段结构

这一步特别适合排查：

  • 字段名对不对
  • 文本有没有空值
  • URL、SKU、品牌有没有导错

若干. 真正开始“使用”Qdrant 的核心流程

Qdrant 真正工作的流程，通常是这 若干 步：

第 若干 步：准备文本

比如一条商品：

  • 品牌：Arista
  • 型号：相关型号
  • 类型：Switch
  • 名称：Arista 若干0LS Switch

你把它整理成一段适合检索的文本，例如：

 SKU: ARI:相关型号 | Brand: Arista | Type: Switch | Model: 相关型号 | Name: 相关型号, Arista 若干0LS Switch, 若干6x1GbE SFP/Ultra Low Latency/Redundant PSU

这就是你现在 pageContent 在做的事情。

第 若干 步：把文本转成向量（Embedding）

Qdrant 本身不负责生成向量。

你需要用别的模型来生成 embedding，比如：

  • OpenAI embedding
  • Gemini embedding
  • BGE
  • Voyage AI
  • 本地 embedding 模型

比如你把一段文本转成一个 若干 维数组：

 [若干, -若干, 若干, ...]

然后再存进 Qdrant。

第 若干 步：把向量和 payload 存进 Qdrant

也就是“入库”。

你现在这一步已经做过了。

入库时，一般会存：

  • id
  • vector
  • payload

第 若干 步：查询时，把用户问题也转成向量，再去搜

例如用户问：

找一款 Arista 的低延迟交换机

流程是：

  1. 把这句话转成向量
  2. 用这个向量去搜 rs-product
  3. 返回最相近的几条商品
  4. 再把结果展示出来，或者交给 AI 总结

这就是 Qdrant 最核心的用法。

若干. Python 最小可用示例

先安装客户端：

 pip install qdrant-client

示例 若干：连接 Qdrant 并查看 collections

 from qdrant_client import QdrantClient client = QdrantClient(url="http://若干.若干:若干") collections = client.get_collections() print(collections)

示例 若干：统计 rs-product 条数

 from qdrant_client import QdrantClient client = QdrantClient(url="http://若干.若干:若干") count = client.count( collection_name="rs-product", exact=True ) print(count)

示例 若干：滚动读取几条数据

 from qdrant_client import QdrantClient client = QdrantClient(url="http://若干.若干:若干") points, next_page = client.scroll( collection_name="rs-product", limit=若干, with_payload=True, with_vectors=False ) for p in points: print("ID:", p.id) print("Payload:", p.payload) print("-" * 若干)

若干. 如果要做“相似搜索”，你还差什么？

你还差的是：

若干）一套 embedding 模型

如果你的 rs-product 向量维度是 若干，那说明你大概率用的是某种 若干 维 embedding 模型。

重点是：

查询时必须用同一套 embedding 模型。

否则会出现：

  • 搜索结果不准
  • 明明有数据却召回很差
  • 相似度看起来很奇怪

若干）一段查询代码

伪代码是：

 query = "arista low latency switch" query_vector = embedding_model.embed_query(query) results = client.search( collection_name="rs-product", query_vector=query_vector, limit=若干 )

然后从 results 里取出：

  • 分数
  • 名称
  • SKU
  • URL
  • 品牌

若干. 建议你怎么开始上手

如果你是小白，我建议按这个顺序来：

第一阶段：先学会“看库”

你先熟悉这些命令：

  • 看 collections
  • 看条数
  • 看样本数据
  • 看某个 collection 配置

只要这几步熟了，你对 Qdrant 就不会陌生。

第二阶段：做一次真实检索

目标：

输入一句话，比如：

  • Arista low latency switch
  • Juniper license
  • 若干0GE modular switch

然后从 rs-product 里搜出最相关的几条。

这一步是从“有数据库”变成“真的用起来”的关键。

第三阶段：给 AI 接上 RAG

典型用法：

  1. 用户提问
  2. 先去 Qdrant 检索商品资料
  3. 把检索结果交给大模型
  4. 大模型基于检索结果回答

比如：

推荐一款适合数据中心的 若干0GE 交换机

系统就能从 rs-product 找到 H3C、Arista、Cisco 等相关商品，再生成回答。

若干. 你这个库目前的一个小优化建议

你现在的 payload 里，很多字段存了两份：

  • 外层一份
  • metadata 里一份

例如：

  • brand
  • name
  • type
  • model
  • url
  • price

这不是严重问题，但后面建议你统一一下。

推荐做法

二选一：

#### 方案 A：只保留扁平字段

 { "sku": "...", "brand": "Arista", "name": "...", "type": "Switch", "model": "...", "url": "..." }

优点：

  • 查询方便
  • 过滤简单

#### 方案 B：只保留 metadata

 { "pageContent": "...", "metadata": { "sku": "...", "brand": "Arista" } }

优点：

  • 结构更清晰
  • 业务字段更集中

对你来说，如果以后要做筛选和接口返回，我更倾向：

保留扁平字段 + pageContent

这样后面开发最省事。

若干. 常见坑

坑 若干：查询时 embedding 模型不一致

这是最常见的大坑。

入库用 A 模型，查询用 B 模型，结果通常会歪掉。

坑 若干：向量维度不一致

比如 collection 要的是 若干 维，但你传了 若干 维，就会报错。

坑 若干：只导入了 payload，没有导入 vector

这样表面上看数据在，实际上没法做向量搜索。

坑 若干：pageContent 太差

如果文本拼得太随便，检索效果会明显下降。

好的 pageContent 应该尽量包含：

  • 品牌
  • 型号
  • 类型
  • 关键规格
  • SKU
  • URL（可选）

坑 若干：以为 Qdrant 自己会“理解文本”

不会。

Qdrant 只负责：

  • 存向量
  • 做近邻搜索
  • 返回结果

真正“把文本变聪明”的是 embedding 模型。

如果你要真正把它用起来，我建议你按这个顺序继续：

方案一：先验证检索效果

这是最推荐的。

方案二：我帮你写一个可直接运行的 Python 脚本

脚本功能可以包括：
